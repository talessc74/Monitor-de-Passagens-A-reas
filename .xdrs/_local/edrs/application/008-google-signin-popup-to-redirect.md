# _local-edr-policy-008: Google sign-in moved from popup to redirect

## Context and Problem Statement

After `flyspot-web` went live and Firebase Authentication was activated (Email/Password + Google,
both confirmed enabled; the `flyspot-web` domain confirmed present in Authorized domains), the
product owner reported "Continuar com Google" always failing with the login page's generic
fallback message. E-mail/senha worked (a real account was created and signed in successfully,
confirmed via browser console traces showing `signUp` completing and Firestore's offline
persistence layer picking up the new session).

Several rounds of asking for browser DevTools evidence (Console, Network with Preserve log) did
not converge on a specific Firebase error code — in one capture no network request at all was
generated by the Google button click, in another the flow visibly started (Google's `gapi`/iframe
loader scripts loading, `signInWithGoogle` appearing in the call stack) but still ended in the
same generic failure. The product owner correctly pushed back that this diagnostic loop had
stalled and asked for the code to be read and fixed directly instead of continuing to guess from
screenshots.

## Decision Outcome

**Replace `signInWithPopup` with `signInWithRedirect` for Google sign-in.**

`signInWithPopup` depends on three origins cooperating correctly at once: the app's own domain
(`flyspot-web-....run.app`), Google's OAuth consent flow (`accounts.google.com`), and Firebase's
auth handler (`lista-ai-f2916.firebaseapp.com/__/auth/handler`), coordinated through a popup window
plus a hidden iframe using `postMessage`. This exact class of failure — works in some environments,
fails silently or generically in others, with no clean error surfaced to application code — is a
well-known, well-documented failure mode of `signInWithPopup` in production (browser popup
blocking, Cross-Origin-Opener-Policy defaults, third-party storage partitioning), and it is
explicitly why Firebase's own documentation recommends `signInWithRedirect` as the more robust
alternative for exactly this situation. `signInWithRedirect` avoids all three-origin popup
coordination: the browser fully navigates to Google, completes auth, and returns to the app's own
URL, where `getRedirectResult()` picks up the outcome.

### Details

- `auth-context.tsx`: `signInWithGoogle` now calls `signInWithRedirect(auth, new GoogleAuthProvider())`
  instead of `signInWithPopup`. A new `useEffect` calls `getRedirectResult(auth)` once on mount to
  catch any error from a completed redirect (this cannot be caught by the caller's local
  `await signInWithGoogle()` the way a popup's promise could, since the page fully reloads between
  initiating the redirect and its result becoming available) and exposes it via a new
  `redirectError` field on `AuthContextValue`.
- `login/page.tsx`: a `useEffect` watches `redirectError` and runs it through the same
  `traduzErro` mapping used for popup/e-mail errors, so the user sees a translated message instead
  of nothing. Two new error codes added to the map: `auth/unauthorized-domain` and
  `auth/account-exists-with-different-credential`, both realistic causes for a Google sign-in
  failure that `signInWithPopup`'s silent failure mode may have been masking.
- Acceptance criterion (verifiable): clicking "Continuar com Google" navigates the full page to
  Google's consent screen (not a popup window) and, after choosing an account, returns to
  `/login`, either landing on `/dashboard` (success) or showing a translated error message
  (failure) — never the previous silent/generic dead end.
- This change could not be validated end-to-end in this sandbox (no browser available) — validated
  by `npm run lint --workspace=@mpa/web` and `npm run build --workspace=@mpa/web` passing clean;
  real confirmation depends on the product owner testing it live once deployed.

## References

- Firebase Authentication documentation explicitly recommends `signInWithRedirect` over

- `_local-bdr-policy-003` — the decision that both e-mail/senha and Google must be supported,
